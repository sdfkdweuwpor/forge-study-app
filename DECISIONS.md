# Decisions

One dated bullet per decision: what we decided, then why. Newest entries go at the bottom of their section.

## Hosting, deploy, tooling

- **2026-09-29 — Deploy to Netlify, not GitHub Pages.** The repo is private on a free GitHub plan, which rules out Pages. Netlify's free tier serves private repos.
  - Vite uses `base: '/'`.
  - The site URL is one constant, `APP_ORIGIN = https://forge-study-app.netlify.app`, defined in `extension/src/shared/config.ts` and re-exported by `src/config.ts`.
- **2026-09-29 — Deploy mechanism.**
  - The coordinator deploys with the Netlify connector or CLI.
  - `.github/workflows/deploy.yml` also deploys with `npx netlify-cli deploy --prod --dir dist` on push to `main`, but only when the `NETLIFY_AUTH_TOKEN` and `NETLIFY_SITE_ID` repo secrets exist (the user adds them).
  - If the user connects the repo through Netlify's Git integration instead, delete `deploy.yml` to avoid double deploys.
  - Nothing is published from the branch until the coordinator deploys it or the user merges to `main`.
- **2026-09-29 — `netlify.toml` holds build, SPA rewrite and cache headers.**
  - Build: `npm run build`, publish `dist`, `NODE_VERSION=22`.
  - SPA rewrite: `/* /index.html 200`.
  - Cache: `Cache-Control: immutable` for `/assets/*`; `no-cache` for `/`, `/index.html`, `/sw.js` and `/manifest.webmanifest`.
  - A missing `/assets/*` file returns a real 404 (`/404.html`), via a rule placed above the SPA rewrite. Redirects only apply where no file exists (no `force`), so existing assets are served normally. Without it, a tab left open across a deploy gets `index.html` in place of a JavaScript chunk and fails with a MIME-type error.
- **2026-09-29 — Security headers come from one file, `security-headers.mjs`.** A 15-line Vite plugin writes it to `dist/_headers`, and the same object feeds `vite preview` headers. Playwright therefore runs under the production CSP, and the header list can't drift between two files.
  - The CSP is `default-src 'self'`.
  - `style-src` adds `'unsafe-inline'`: some libraries inject `<style>` elements or style attributes, and with `script-src 'self'` it cannot run script. React `style` props alone would not need it.
  - `font-src` adds `data:`, because Vite inlines small font subsets as data URIs.
  - `worker-src 'self'` only: workers are separate built files (`new Worker(new URL(...))`), never `blob:` or `?worker&inline`.
  - `img-src` adds `data:`, `blob:` and `https://icons.duckduckgo.com`.
  - `frame-ancestors 'none'`.
  - The theme bootstrap is an external `/theme-init.js`, so no inline scripts are needed.
- **2026-09-29 — Extension releases stay on GitHub Actions.** Releases work on private repos. Download links need the user to be logged in to GitHub, which is fine for a single user.
- **2026-09-29 — No Playwright MCP here, so verification uses a Playwright script.** `npm run shoot` runs `scripts/shoot.spec.ts` through the Playwright test runner, which gives TypeScript without `tsx`.
  - It serves the preview build, fixes the clock and seeds sample data.
  - It saves light/dark × 1440/375 PNGs to the git-ignored `screenshots/`. Agents review them with Read.
  - Curated shots for the README are committed under `docs/screenshots/` in Phase 13.
- **2026-09-29 — Pin `@playwright/test` to exactly `1.56.1`.** The environment ships chromium-1194 in `/opt/pw-browsers` (`PLAYWRIGHT_BROWSERS_PATH`) for that version. Never run `playwright install` locally; CI may install its own browser if e2e is ever added there.
- **2026-09-29 — CI (`ci.yml`) runs typecheck, lint, unit tests and build on every push and PR. e2e runs only in agent sessions.** This keeps the private repo within its 2,000 free Actions minutes.
- **2026-09-29 — Node scripts are plain `.mjs`; Playwright handles `.ts` specs.** This avoids adding `tsx` or `ts-node`.
- **2026-09-29 — PWA icons are rasterized from `favicon.svg` by `scripts/icons.mjs` using Playwright's Chromium.** This avoids `sharp` and `@vite-pwa/assets-generator`.
- **2026-09-29 — Lighthouse runs in Phase 13 via `npx lighthouse` with `CHROME_PATH` pointing to the bundled Chromium.** It is a one-off audit, so it isn't added as a dependency.
- **2026-09-29 — Subagents live in `.claude/agents/` and are invoked by type** (architect, designer, builder, reviewer, helper) with the `model:` from their frontmatter. Phase 0 ran through the general-purpose agent with an opus override because the session hadn't loaded the new types yet; they are loaded from Phase 1 on.
  - Parallel builders get disjoint file-ownership lists (PLAN §6).
  - Edits to shared files are serialized by the coordinator.

## Architecture

- **2026-09-29 — Routing uses a hand-written history router with typed routes, not react-router.** Netlify's SPA rewrite plus the PWA `navigateFallback` make clean paths safe, and they read better in breadcrumbs and shared links.
  - The router is about 150 lines. We only need a route table, params, an optional last segment, `Link`, `navigate`, `href`, `useRoute` and `useQuery`.
  - All URL access sits in `router/location.ts`. Switching to hash routing, for a host without rewrites, is a contained change.
  - `vite dev` and `vite preview` already fall back to `index.html`.
- **2026-09-29 — The complete route table is central, and features auto-register through `import.meta.glob('features/*/feature.ts')` manifests.** These provide routes, commands, shortcuts, search, slots, providers, domain handlers and `onAppStart`. Parallel builders then almost never edit the same file, links stay type-safe, and every route is lazy-loaded.
- **2026-09-29 — Named UI slots** (e.g. `course.panels`, `today.aside`, `settings.sections`). A later phase can add UI to another feature's page without editing it, which matters most for the 9 parallel extras in Phase 11.
- **2026-09-29 — Dexie liveQuery hooks are the store. Writes go only through `src/db/repos/*`. Contexts hold UI state only.** There is one source of truth, no cache invalidation, and no Redux or Zustand.
- **2026-09-29 — Domain events are emitted after commit (`src/db/events.ts`), and features subscribe to them.** This decouples derived data (streakDays, badges, daily-goal XP) from the core writes, and derived data can be rebuilt from history in `onAppStart`. The core XP award stays inside the task or session transaction, so undo is exact.
- **2026-09-29 — Layer rules are enforced by lint.** `logic/` is pure: no React, Dexie or DOM, and time is injected. `ui/` has no data access. Features import other features only through `index.ts`. That keeps logic testable and boundaries honest when many agents edit.
- **2026-09-29 — Use date-fns v4, not Temporal.** It is tree-shakeable and stable with no polyfill.
  - Calendar days are local `'YYYY-MM-DD'` strings; instants are epoch ms.
  - Never use `new Date('YYYY-MM-DD')`, because it parses as UTC.
  - Tests run with `TZ=America/New_York` to exercise DST.
- **2026-09-29 — TypeScript `strict` plus `noUncheckedIndexedAccess`.** The scheduler and stats index arrays heavily, and this catches off-by-one and undefined bugs at compile time.
- **2026-09-29 — IDs come from `crypto.randomUUID()`.** It is available in secure contexts (Netlify HTTPS, localhost) and needs no dependency. Natural keys are used where they're more robust: settings `'app'`, streakDays by day, badges by badge id, rituals `kind:day`, weekly reviews by week start, block events by extension uuid. These make idempotent upserts trivial.
- **2026-09-29 — Shortcut scopes: overlay scopes are blocking, and the controller alone decides what is live (Phase 3F).** The `modal`, `palette`, `fullscreen` and `drawer` scopes (`BLOCKING_SCOPES`; `pushScope(scope, { blocking })` overrides per push) hide everything beneath the topmost one. While one is on top, only its own shortcuts, scopes pushed above it (a scope opened inside a dialog) and `global` shortcuts with `allowInOverlays` may fire. That flag is separate from `allowInInputs`: `true` keeps a shortcut live under any overlay (`esc`, `mod+k`, `mod+enter` "quick add from anywhere"), and a list of scope ids keeps it live only under those (`mod+\` is `['drawer']`, so it still closes the tablet drawer but no longer collapses the sidebar behind a dialog). Everything else global (`q`, `g t`, `?`, `/`) goes quiet under an overlay.
  - Esc resolves the same way, with no special case: under an overlay the global `app.escape` (or the overlay's own `esc`) is the only Esc candidate, so the top overlay closes first; a page's `tasks.escape` gets Esc only once no overlay is open. `escapeActive` and the `useOpenOverlays().length === 0` guards in the tasks, view and Today hooks were removed. The Tasks page had the bug at 640-1023 px, where `escapeActive` was never passed. Two overlays that both bind `app.escape` (the drawer and `OverlayEscape`) still resolve by bind order, which matches open order because the only global that can open something under an overlay, `mod+\`, is limited to the drawer.
  - The Tasks page's `x`/`j` now also stop under the tablet drawer and the More sheet, which are not in `OverlayProvider` and were never covered by those guards. The drawer has its own `drawer` scope (it was `modal`, whose `mod+enter` "next step" in wizards must not run in a navigation drawer); `SCOPE_LABELS` names it.
  - `src/ui/Modal` cannot import the app, so it reports through `ModalPresenceContext` (`ui/Modal/ModalPresence.ts`): `Modal` calls the provided function while `open` and calls what it returns on close. `ShortcutProvider` provides one that pushes the blocking `modal` scope, so any Modal (the shortcut sheet, `/design`, the Phase 5 wizards) blocks the page with no per-caller code; the sheet's own scope push was dropped. Without a provider it does nothing. The palette and quick add still push `palette` and `modal` themselves. A Phase 4 full-screen focus view should push `fullscreen` and mark `p` (park a thought) `allowInOverlays`.
  - Menus and popovers report the same way, with kind `'menu'` (`FloatingLayer`, so `Dropdown` and `Popover`): `ShortcutProvider` pushes a blocking `menu` scope, the lightest overlay (no shortcuts of its own; `allowInOverlays: true` keys such as `mod+k` stay live). While one is open, a page key the menu does not use itself (`Mod+Backspace` trashes, `Alt+↓` reorders) no longer fires behind it, and neither does a key pressed while focus is still on the trigger. `DatePicker` is inline native inputs and needs nothing; inside a popover it is covered. Menus and popovers still take Esc first through `ui/Popover/layers`.

## Data model

- **2026-09-29 — Schema v1 defines every table up front: the 21 in BRIEF §6 plus 5 extra.** The extras are `savedViews` (Notion-like saved views, §5.3), `rituals` (§5.11), `weeklyReviews` (§5.7), `templates` (§5.11) and `files` (PDF blobs kept apart, so resource lists and snapshots stay light). Later phases then almost never need a migration.
- **2026-09-29 — Migrations are append-only.** Never edit a released version string. Each new version gets its own `migrations/vN.ts`, a matching backup-file migrator, and a fake-indexeddb upgrade test. Old backups and snapshots must always restore.
- **2026-09-29 — Timestamps are stamped by Dexie `creating`/`updating` hooks, which only fill missing values.** Builders can't forget them, and restore and trash-restore keep the original timestamps.
- **2026-09-29 — Booleans and nullable fields are never used as index keys.** IndexedDB can't index booleans, `null` or `undefined`. Nullable dates simply drop out of the index; booleans are filtered in JS.
- **2026-09-29 — Trash moves the record, and its cascade, into a `trash` row with a JSON payload and a 30-day expiry, instead of a `deletedAt` flag.** No query ever has to remember to filter out deleted rows, and restore is one `bulkPut`.
- **2026-09-29 — `xpEvents` is append-only.**
  - Undo writes a negative event with the same `key`.
  - Awards are idempotent per key: skip if the key's net is > 0.
  - Lifetime XP is the sum of all events. Balance is lifetime minus unrefunded redemptions. Levels use lifetime XP.
  - This follows the brief: XP must never drift and must be auditable.
- **2026-09-29 — Levels: advancing from level n to n+1 costs `round(100·n^1.5)`, starting at level 1 with 0 XP.** This matches the brief's sidebar mock ("Level 7 … /1,800", and L7→8 = 1,852).
- **2026-09-29 — `streakDays` is a rebuildable daily aggregate cache. The streak freeze is computed, not stored.** The day's daily-goal target is snapshotted so later settings changes don't rewrite history. At most 1 freeze per week (by `weekStartsOn`). A frozen day keeps the streak but doesn't add to it.
- **2026-09-29 — Breaks are stored as `sessions` rows (`kind: 'break'`), and timers are always computed from timestamps.** The whole pomodoro cycle survives a refresh. Stats filter on `kind = 'focus'`.
- **2026-09-29 — Timer ticks run in a module Web Worker.** Hidden-tab main-thread timers are throttled to about once a minute, which would make the chime and notification late.
- **2026-09-29 — Anti-cheat:** a session counts if it reaches 80% of planned time. Stopwatch sessions have no plan, so they count at 10 minutes or more.
  - **2026-09-30 — It compares exact time, not whole minutes** (`elapsed × 5 ≥ planned × 4`: 9:59 of a 12-minute plan counts); XP stays whole minutes. A stopwatch is paid and counted for at most 4 hours, so one left running overnight cannot farm XP or fake a streak day. A planned session that is finished late ends at its planned end, not at "now".
  - **2026-09-30 — An early stop can be taken back.** A focus session that ended without counting (under 80%, or a stopwatch under 10 minutes) offers Undo in its toast (`reopenSession`): it runs again, and the wait is added to `pausedMs`. A counted session paid XP, so it is not undoable.
- **2026-09-30 — Focus with several tabs open.** Only one tab wins the settle at the end of a phase, so the "Done with this task?" queue is shared through `forge:focus:pending-end` (storage events): every visible tab asks it, answering in one closes it in the others, and a newer question waits behind an open one. One tab plays the ambient bed, elected with a Web Lock (`navigator.locks`); without Web Locks each tab plays as before. Audio is unlocked (the context created) only when sounds are on.
- **2026-09-29 — Priority is stored as a number (0 none to 4 urgent).** It sorts and compares for free. Labels are mapped in logic.
- **2026-09-29 — Subtasks are an embedded checklist array on the task, not separate task rows.** This matches Things/Notion checklists and keeps queries simple.
- **2026-09-29 — Notes (task, goal, course) are a small `Block[]` model with a hand-made block editor and slash menu.** The brief asks for `/todo /heading /divider /callout` only, which doesn't justify a rich-text dependency.
- **2026-09-29 — Device-specific UI prefs (sidebar width/collapsed, last tasks layout, a theme mirror for no-flash boot) live in `localStorage` behind try/catch. Everything else lives in the `settings` row.** Those prefs shouldn't sync between laptop and phone.
- **2026-09-29 — Sample data comes from `?seed=wgu|empty`, which lazy-imports `src/dev/seed.ts`, and only in builds compiled with `VITE_ENABLE_SEED=1`.** It is used for screenshots and e2e (realistic WGU data: C182, C172, C779, D278, C959, C867, C949).
  - `npm run dev` and both Playwright `webServer` commands set the flag. A deployed build never has it: the seed module is dropped from the bundle and `?seed=` is ignored (and stripped from the address). A crafted link therefore can't replace anyone's data, whether or not the database already holds any.
  - Never set `VITE_ENABLE_SEED` in Netlify's environment.
- **2026-09-29 — `TaskFilter`/`TaskSort` live in `src/db/types.ts`, not `logic/taskQuery`.** `SavedView` needs them, and `db` must not depend on `logic` for types; `logic/taskQuery` imports them from `@/db/types` instead.
- **2026-09-29 — Tables are typed `Table<T, ID, NewRow<T>>`.** `add`/`put` accept rows without `createdAt`/`updatedAt` because the hooks stamp them; reads always return full rows.
- **2026-09-29 — Stamping edge cases.** An explicit `updatedAt` in a change is kept (sync/import); a `put()` that omits `createdAt` keeps the stored one; an empty diff is not stamped. `ForgeDB(name, clock)` takes an injectable clock for tests.
- **2026-09-29 — New settings fields need no Dexie migration.** `ensureSettings()` (boot) backfills keys missing from `defaultSettingsData()` into the stored row; `getSettings()`/`useSettings()` apply the same backfill in memory and never write.
- **2026-09-29 — `useSettings()` is `undefined` only while loading; with no row it returns factory defaults.** "No row" means a fresh install, where defaults are the truth, and the shell can distinguish loading from loaded.
- **2026-09-29 — `updateSettings(patch)` merge rules:** plain objects merge key by key (including `tagColors`), arrays replace, `undefined` is ignored, `null` sets null, and `id`/timestamps can't be patched. Removing a tag color will need a dedicated repo function (Phase 3).
- **2026-09-29 — Event bus mechanics.** `emit()` inside a transaction queues on the *root* Dexie transaction's `complete` event and is dropped on abort; outside a transaction it dispatches on a microtask. Handlers run under `Dexie.ignoreTransaction` so they can open their own transactions. `settleDomainEvents()` awaits everything in flight (tests, boot). `DomainHandler` is a union over event types, built with `defineHandler()`.
- **2026-09-29 — `newId()` falls back to `crypto.getRandomValues` when `randomUUID` is missing.** `randomUUID` needs a secure context, and the dev server is sometimes opened over a LAN IP from a phone.
- **2026-09-29 — Task repo conventions (Phase 3A).** `createTask` appends with `order = Date.now()`, so adding never scans the table; reordering uses fractional `orderBetween(above, below)` and renumbers the whole list only when two neighbours are closer than 1e-3. `updateTask` cannot change `status`: `setTaskStatus` routes done through `completeTask` and back through `uncompleteTask`, so XP and recurrence cannot drift. Editing the date or time of a `source: 'schedule'` task pins it (`schedulePinned`), as the scheduler decision requires.
- **2026-09-29 — Completing a recurring task creates the next instance in the same transaction, on the first occurrence after both its due date and today.** A daily task finished three days late is next due tomorrow, not in the past, and an every-other-week series keeps its phase. The new row shares `seriesId` and keeps the checklist unchecked. Undo removes exactly that row; reopening a task by hand removes the generated instance only while nobody has touched it.
- **2026-09-29 — An XP reversal is filed under the day of the award it cancels, with `at` set to when the undo happened.** That day's total nets out, and "XP today" never shows a negative number because you undid yesterday's task. `awardXp` skips a key whose net is positive; `reverseXp` appends the negative of the standing net; `getXpSummary` is derived from the log and redemptions on every read.
- **2026-09-29 — Trash is generic over tables.** `moveToTrash(table, id)` gathers a task (its checklist is embedded), a course (units, tasks, assessments, flashcards, resources and their files) or a goal (all of that plus its own tasks) into one `TrashItem` in one transaction. Restore is `bulkPut` per table, so ids and timestamps survive, and it emits `task.changed` / `goal.changed` for what came back. XP events are never trashed. `purgeExpired(now)` exists but is not wired to `onAppStart`; that belongs to Phase 11c.
- **2026-09-29 — Undo closures use the time they run, not the time of the action.** The `now` option on repo functions is for tests only; a reversal recorded by an undo an hour later says so.

## Scheduler

- **2026-09-29 — Courses are scheduled sequentially from one queue, in topological prerequisite order.** Priority is: active course first, then `order`, then code. This matches how WGU students take courses (one at a time) and makes prerequisites automatic. A cycle is reported and ordering falls back to `order`, so the preview still renders.
- **2026-09-29 — Chunk rules.**
  - Chunks are 25–90 min, in 5-min steps, and a day never goes over its capacity.
  - Tiny tails are avoided by leaving one 25-min final chunk. When that isn't possible, a short final chunk is accepted.
  - If a user's whole week is under 25 min/day, the minimum chunk drops to their largest daily capacity (`minEff`), so a schedule can't stall.
- **2026-09-29 — The schedule is materialized as real `tasks` (`source: 'schedule'`) and reconciled by `diffSchedule` on a stable `scheduleKey = unitId:seq`.** Goal work then appears in Today, Board, Calendar and .ics with no special cases, and user notes on chunks survive rebalances.
- **2026-09-29 — Manual date edits pin a scheduled task, and the rebalancer leaves pinned tasks alone.** Pins expire once their date has passed. This respects the user's choices without letting stale pins block progress.
- **2026-09-29 — Rebalance runs automatically at the first app open each day, and on edits, early completion, skip and catch-up.** Skipped tasks reserve their minutes for today so they move forward.
- **2026-09-29 — Catch-up is found by linear search in 5-min steps.** "Add X min/day" is the smallest X that is actually verified by re-running the scheduler. "Required h/day" is a verified uniform capacity. Both are correct even where the chunking makes feasibility non-monotonic.
- **2026-09-29 — Availability is per goal, and multiple goals don't share one capacity pool.** This is a documented limitation that keeps the algorithm simple. Global days off apply to all goals.
- **2026-09-29 — The slip ("+9 days") is measured against `targetDate`, or against the accepted plan's `baselineEnd` when there's no target.** The brief shows slip relative to a promise.
- **2026-09-29 — Scheduler as built (Phase 5A): the chunk rule.** `take = min(90, unit remainder, day left)`; if that leaves a tail under minEff and the unit is at least 2 × minEff, take `remainder − minEff` so the last piece is exactly minEff (100 min on a 120-min day is 75 + 25); a day with less than minEff left only takes a unit's whole remainder. So every chunk is 25–90 min (minEff–90) except a unit's final chunk. Greedy, as-soon-as-possible filling: each day is filled to its capacity from the head of the queue, which is what "push work forward, never above the daily max" means, and makes a missed day shift the plan by exactly one study day.
- **2026-09-29 — The scheduler walks integer day numbers, not `Date`s.** Days are counted from 1970-01-01 with Hinnant's civil-date arithmetic (`capacity.ts`), so there is no clock time and DST cannot duplicate or drop a day; a test checks them against date-fns across both 2026–27 DST changes and a leap day. It is also fast enough for catch-up to re-walk dozens of times: a 12-course year plans in about 1–4 ms and plan + catch-up in under 5 ms (the test budget is 50 ms).
- **2026-09-29 — Keys reuse free numbers.** A new chunk takes the smallest chunk number not held by a done or pinned chunk of its unit (`usedSeqs`), not simply "after the last done one". Finishing chunk 3 before chunk 1 then leaves the open tasks' keys (1, 2, 4) unchanged instead of renumbering the whole unit. The title's "(2/4)" is the key's number over done + pinned + planned chunks.
- **2026-09-29 — Pinned work is its own input (`ScheduleInput.pinned`), not just reserved minutes.** It still consumes its day's capacity, but it also counts toward `projectedEnd` and the course window, so dragging the last chunk two weeks out moves "Now projected" too. A pin lapses when its day has passed, when the task is skipped today (skip beats pin), or when its unit or course is done. A pinned task with no date is left alone and uses no capacity.
- **2026-09-29 — Skipping defers, it does not just reserve.** Skipped minutes reserve today's capacity (PLAN §4.3) and are also marked `deferredMinutes` on their unit, which may not land on today; on today only the rest of the unit is available (in pieces of at least minEff) and the walk looks past it to later units. Without that, a skipped chunk at the head of the queue came straight back to today. The diff never matches a task skipped today to a chunk dated today: it takes a later chunk of its unit, swapping keys with an unskipped task if needed, so the skipped task moves and the rest of today stays as it was. Idempotent on the next run.
- **2026-09-29 — Today's finished chunks reserve their minutes today.** Finishing a chunk does not pull tomorrow's work into today; working ahead on tomorrow's chunk pushes one of today's to tomorrow. Only `source: 'schedule'` tasks count (flashcard reviews and the user's own goal tasks do not use goal capacity yet).
- **2026-09-29 — Dropped chunks with user content go to the trash, detached.** An unneeded chunk (its unit was finished or shortened) is deleted outright only when untouched; one with notes, a checklist, tags, a priority, or in progress is turned into a plain task (`source: 'user'`, no key) and moved to the trash, so it can be restored and the rebalancer will not delete it again. Unmatched tasks are first re-keyed to a free chunk of the same unit, which keeps notes when a unit is re-chunked.
- **2026-09-29 — `rebalanceGoal` writes only what changed.** Tasks are updated field by field, courses and the goal only when their dates or projection differ (ignoring `computedAt`), and events fire only then; a second run the same day writes and emits nothing. So a `goal.changed` → rebalance handler settles after one extra run. It plans any goal it is given; the daily run decides which statuses to include. `baselineEnd` is set on `reason: 'wizard'` or when the goal has none.
- **2026-09-29 — Catch-up aims at the same date the slip uses (`targetDate ?? baselineEnd`).** PLAN §4.2 only suggested catch-up with a target; without one the goal page would show "+9 days" with no way to act. `projectedEnd` is `null` for `NO_AVAILABILITY` and `HORIZON_EXCEEDED` (a partial last date would look like a real end).
- **2026-09-29 — Units vs course hours.** When every unit has an estimate, their sum is the course's work (the WGU sample's D278 units add up to 34 h against 45 h on the course); units without one share what is left of the course hours in 5-min steps, and get 0 when nothing is left. A course without units is one synthetic unit (id = course id, "Study session", `unitId: null` on its tasks). Cycle members are released one at a time from the "source" component, so courses that merely depend on a cycle still come after it.

## Planner (Goal Breakdown Planner, slot-level)

- **2026-09-30 — The slot planner is a new entry point (`planStudy`) beside the day-level scheduler.** `buildSchedule`, `planGoal` and `diffSchedule` are unchanged and keep serving v1 goals until 5G switches `rebalanceGoal` over. All the new logic is pure and lives in `src/logic/scheduler/`, and parsing in `src/logic/planParse/`. There are no schema changes before 5G, because three builders are editing the repos in parallel.
- **2026-09-30 — Availability v2 is windows, not minutes.** It is per-weekday `HH:mm` windows (several a day, `24:00` allowed as an end; an overnight shift is two windows), a session length, blackout ranges, and an optional shift cycle (anchor + N days) that replaces the weekdays. Blackouts still apply over a shift cycle. The v1 `minutesByWeekday` becomes one window per study weekday starting at `settings.scheduling.defaultStudyStart` (the logic default is 18:00). It moves earlier when it would run past midnight.
- **2026-09-30 — DST: the skipped hour (spring) and the repeated hour (autumn) are taken out of that day's windows.** Wall-clock length then always equals real length, and no session straddles a change. The only loss is study planned 1–3 a.m. on two nights a year. The DST span is found with `new Date(y, m, d, h)` in the runtime zone, the same local-time assumption `logic/dates.ts` makes.
- **2026-09-30 — Effort: hours, else CUs × a user multiplier (default 15 h/CU: a 3-CU course ≈ 45 h), × a self-rating factor (know 0.5, somewhat 0.8, new 1.0).** The factors are rough "how much is left to learn" shares; the multiplier is the user's to tune. v2 keeps `baseEstimateMinutes` so re-rating recomputes.
- **2026-09-30 — The buffer is reserved capacity at the tail, not inflated effort.** 12 % of the planned work (10–15 % in the UI) is walked as free time after the last item at the plan's pace, giving `bufferedEnd`, and the plan fits when that is on or before the target. Inflating the sessions instead would make an on-track student do 12 % extra work. Tail slack is also what missed work rolls into.
- **2026-09-30 — Study is split as it is placed, not pre-split.** The planner first sized every session to the target length up front. With 50-min sessions that wasted up to a third of a 90-min window, and the WGU year at full speed ended in February 2028 instead of November 2027. Now a piece is the first of an even split when it fits, otherwise a piece of at least 25 min that fills the window without leaving under 25. A unit that fits in one session is never broken up. `splitMinutes` stays as the even split (readiness reviews, first-piece sizing).
- **2026-09-30 — A 10-min break between planned sessions, when there is room; back to back when not.** A hard break made a 2-hour window hold only one 60-min session.
- **2026-09-30 — Pace: ASAP without a target; with one, the smallest verified pace.** The pace is a token bucket (each study day adds `pace`, capped at pace + the longest item), so the average is exactly `pace` even when sessions are longer than it, and a day gets at most one extra session after days that could not use theirs. The pace is found by binary search, and every candidate is a real run. The first cap, max(pace, longest item), threw tokens away and under-delivered the pace. `planning.asap = true` with a target means full speed with the target only checked.
- **2026-09-30 — Assessments.** A dated one is fixed: a booked time blocks its slot, and without one it is a day marker, because the student books exam times. Its practice test and reviews are placed first, on study days before it: exam −7/−3/−1 plus practice −2; quiz −1; project −2. Offsets are scaled by gap/(max+1) when fewer study days are left and deduplicated against the practice day. An undated one is placed on the first study day after its course's last item, and gets that day's first free slot. Its extras are due at the point of the course's work that is about k study days from the end, so no second pass is needed. Study on or after a dated assessment of its course (`ASSESSMENT_TOO_EARLY`) makes the plan not fit.
- **2026-09-30 — Weekly milestones are derived markers** (`milestone:${weekStart}`), one per week with work or an assessment. They are dated on that week's last day with work and say which units finish that week ("Week of Oct 5 — finish C182 Units 3–4"); a week that finishes none says "continue …". Unit numbers are positions in the course, and courses are listed in plan order. Month names are fixed English, so titles do not depend on the locale.
- **2026-09-30 — Feasibility options are all verified by re-running the planner.** The searches use full-speed runs, which fit exactly when some pace fits. Add-time is a binary search over +5-min steps up to +4 h, applied as a later end of each day's last window (then an earlier start). Move-date is the full-speed `bufferedEnd`, checked. Cut-scope is greedy in candidate order (optional, then "know", "somewhat", then latest in the plan), then pruned; it is never "cut everything". The shortfall comes from the run itself: work after the target, the part of the buffer the target cuts off, and study after a dated assessment. A raw capacity estimate ignored breaks and said "5 min short" when 170 min were missing.
- **2026-09-30 — Roll-forward is move-only and push-only.** Keys, lengths and order are kept, and an item never moves earlier than its slot. Missed items (slot before today, or before `now` when given) take the next open slots, and later ones move only as far as needed. A paced plan keeps its pace with the planner's bucket, started full, so an on-track plan reflows to exactly itself and a missed session is absorbed in the headroom first. A missed review or practice test goes to the nearest free slot before its assessment, or is dropped (reported). A pin lapses when its day passes. Re-splitting or re-pacing is a proposal, never automatic.
- **2026-09-30 — Behind thresholds.** *Far behind* means any of:
  - the end slips more than 7 days past the baseline end (else past the previous end);
  - missed work is more than 15 % of the remaining work;
  - the end passes the target;
  - study lands on or after a dated assessment.

  Otherwise a plan with misses is *slightly behind*, and its roll-forward may be applied silently (`autoApply`). Far behind returns proposals (keep going, extend date, add time, cut scope, spread) and applies nothing. In ASAP mode "extend the date" is accepting the new end (it resets the baseline).
- **2026-09-30 — "Life happened" (`replanWeek`) is always a proposal.** It clears the rest of the week by default (capacity factor 0), or only the `blockedDays` given, or keeps a share of each window (`capacityFactor`). The week's work moves later, push-only; pinned items and reviews on cleared days move too; a booked exam stays.
- **2026-09-30 — Everyday auto-slot: earliest due first, then shortest, each at its earliest open slot that ends before it is due.** Tasks are never split; a task with no estimate counts as 25 min; the results are `noRoom` or `pastDue` otherwise. Earliest-deadline-first is the classic order that meets the most deadlines on one timeline. Opting a task in (`autoSlot`) is the confirmation, so applying its slot needs no further prompt.
- **2026-09-30 — `planParse` is line heuristics, not a grammar.** Noise lines are ignored. Course lines start with a code (`C182`, `CS 101`) and carry CUs, credits, OA/PA and hours. Headers (week, module, chapter, unit, lesson, …) are units, and whatever sits under one is its details. Assessments are exam words anywhere, or project words at the start when dated, due, or top-level; review, prep and practice lines are study. A single line, or text with no structure, is a typed goal (`needsBreakdown`, and its deadline read from "by June 2027" or "in 6 months"). Numeric dates are month first. A date without a year takes the year that puts it at most 60 days back. It outputs the shared `PlanDraft` from `planImport/draft.ts` (a type-only import) and keeps `needsBreakdown` and `confidence` on the result, so the import builder's type is not changed.
- **2026-09-30 — v2 task dates: `doDate` = when to do it, `dueDate` = a hard deadline only.** The migration moves every v1 `dueDate/dueTime` to `doDate/doTime` and clears the due fields. The single v1 date always meant "the day to do it" (quick add, the scheduler, Today), and turning every task into a deadline would light up false "overdue" badges. "Rolled over" reads `doDate`; "overdue" reads `dueDate`. Planner items get a `dueDate` only when an assessment bounds them.
- **2026-09-30 — Planned assessments get their own table (`plannedAssessments`), separate from `assessments` (attempt logs with scores).** One is a plan and the other a history, and readiness will join the two.
- **2026-09-30 — Performance.** A 12-course year with reviews, milestones and slots plans in about 10–16 ms paced (about 8 runs) and 3–5 ms ASAP; the test budget is 50 ms. Windows per day are memoized across the pace search, and each run's free time is a lazy per-day map.
- **2026-09-30 — Schema v2 applied (5G): one pure row mapping for the upgrade and for backups.** `logic/schemaV2.ts` maps each row idempotently; `db/migrations/v2.ts` runs it in the Dexie upgrade and `logic/backup.ts` (`migrateBackupV1toV2`) runs it on backup tables, so an old backup imports exactly like an upgraded database (a test checks they are equal). Trash payloads are mapped too, because restoring a v1 row after the upgrade would otherwise bring back an old-shaped row. The WGU planned assessments get ids derived from the course (`${courseId}:oa|pa`), so re-running cannot duplicate them, and a finished course's are created done.
- **2026-09-30 — A migration does not stamp `updatedAt`.** The timestamp hook skips rows changed inside the native `versionchange` transaction (Dexie wraps upgraders in a `'readwrite'` transaction, so the hook checks `tx.idbtrans.mode`). Otherwise every row would look freshly edited after the upgrade, which would matter for last-write-wins sync.
- **2026-09-30 — A task with a deadline but no do date is planned for its deadline (`planDay = doDate ?? dueDate`).** Today, Upcoming, the board and the calendar read `planDay`, so "Pay the phone bill, due Fri" shows up on Friday even though nobody picked a day (and auto-slotting, when opted in, picks an earlier one). The deadline itself never moves a task between lists, is never red, and is amber only on its day. A date filter keeps its stored name (`due`) so saved views and links still work; it now means the planned day.
- **2026-09-30 — No guilt: "Rolled over" became "Carried over", and nothing says "overdue".** Each carried-over row says the day it came from ("from Tue"), the group header and the date chip are neutral (no amber), the date group in lists is "Carried over", and the calendar's accessible name says "carried over". "Move all to today" stays (`shift+t`, and the palette command now named "Move carried-over tasks to today", which still matches "rolled over").
- **2026-09-30 — Quick add: a plain date or time is when to do it; `due`, `by` and `deadline` make a deadline.** "pay bill Fri" is planned for Friday, "pay bill due Fri" is due Friday (and planned for its deadline until moved). A time right after a deadline date, or after `by`/`due`, is the deadline's time; with no deadline date it falls on the do date, else today. `by` now always means a deadline ("Submit essay by 5pm"), which reads as intended. The result has `when` and `deadline` instead of `due`, and deadline chips are their own token kind.
- **2026-09-30 — `rebalanceGoal` runs the slot planner; the day-level scheduler stays for its tests only.** Plan items become tasks by key with their kind, do date and time, duration and (for reviews, practice tests and assessments) the assessment date as deadline. Weekly milestones are real tasks too (day markers without a time). The day-level code was moved to `doDate` so it stays coherent, but nothing in the app calls `planGoal` any more; the wizard preview uses the same `planGoalSlots` the repo does.
- **2026-09-30 — Skipping a session takes its length off the end of today.** The planner has no "deferred minutes"; blocking the skipped slot itself was not stable (once the task moved, the next run no longer knew where it had been and put work back into the slot). Reserving the same length at the end of today's windows is deterministic across runs, gives today one session less, and moves the skipped task to a later session of its unit (the diff's skip passes). Sessions finished today keep their own slot blocked, so finishing early does not pull more work in.
- **2026-09-30 — Everyday tasks with a do time, and other goals' sessions, are blocked slots for a goal's plan.** One person cannot be in two places; goals are still planned one at a time, so the first one planned gets the slot (the next run of the other plans around it).
- **2026-09-30 — A planned assessment counts as done when its item is checked off or its course is marked done.** Checking off "C779 · Objective assessment" stops its reviews from being generated; marking a course complete (WGU: passing it) needs no exam.
- **2026-09-30 — Proposals are rows, applied only on confirmation, and go stale.** `rollForwardGoal` writes the far-behind choices as `planProposals` (pending) and changes nothing else; a later run marks older pending ones stale. `applyProposal` refuses (marks stale) a proposal computed on another day or from a different open plan (`baseRevision` = a fingerprint of the open items). Move-only proposals (roll forward, "life happened") carry their items and are written as they are; the others change the goal (target date, windows, pace) or trash the cut units and then re-plan. Undo restores the goal, units, plan tasks and proposal statuses from a snapshot. `apply` is checked by a hand-written guard, not Zod, because the repo is in the first chunk. The daily run is `runDailyPlanning`, gated by `settings.scheduling.lastDailyRunDay` and skipping goals already planned today; the goals feature starts it from `onAppStart` with a dynamic import.
- **2026-09-30 — Legacy minutes become windows as they are, breaks included.** "2 h on Mondays" is a 09:00–11:00 window (from `defaultStudyStart`), and the planner's 10-minute breaks between 50-minute sessions come out of it, so a window holds a little less study than its length. That is the honest reading of "I have two hours", but it made the WGU template and sample miss their terms, so their windows were widened (template Mon–Fri 2.5 h, Sat 4 h; sample Sun/Fri 1.5 h, Mon–Thu 2 h, Sat 3 h). Planning windows and weekday minutes are kept in step by the repo (`logic/goalPlanning.ts`): new minutes rebuild only the changed days' windows from where each started; new windows rewrite the minutes; `asap` is kept.
- **2026-09-30 — Hooks for later phases, with no UI:** `logic/readinessPlan.ts` maps `readiness` rows to the planner's `extraReviewMinutes` (and suggests minutes for a score); `logic/practice.ts` computes the wrong-answer queue from `questionAttempts`; `Task.sync` and the flashcard `scheduler`/`fsrs`/`noteRef` fields exist and are filled by the upgrade.
- **2026-09-30 — Everyday tasks and the Week view (5H).** Quick add reads a length (`30m`, `1h`, `90min`, `1.5h`, `1h30m`) as `durationMinutes`; `sat` counts as a day when a length follows it ("call mom sat 30m"). Chips merge a date and its time: "Do: Tomorrow 6:00 AM" for when to do it, "Due: Fri, Oct 2" for the hard deadline. A passed deadline reads a neutral "Was due Tue".
- **2026-09-30 — Suggested times reuse `settings.scheduling.taskWindows` (no new `settings.tasks` key).** Its default is now weekdays 18:00–21:00 and weekends 10:00–18:00; a stored 09:00–21:00 on all seven days (the earlier default) is read as never changed. `proposeAutoSlots` (`db/repos/autoslot.ts`) is read-only: earliest deadline first around timed tasks and plan sessions, plus the global days off. Accept sets the do date, time and length and turns `autoSlot` off; Dismiss turns `autoSlot` off, which is why it needs no extra storage. Each has Undo. The `AutoSlotSuggestions` card is exported from `@/features/tasks`; shortcut `shift+a` accepts all, and the palette has "Accept suggested times". Opting a task in is the toggle on its page (quick add has no token for it).
- **2026-09-30 — Week blocks.** A block's length is `durationMinutes`, else the estimate, else 30 minutes (minimum 15). Drag the bottom edge (snaps to 15 min) or press Alt+Shift+↑/↓; resizing a plan session pins it, like moving it. Only plan sessions and anything filed under a goal or course take a goal colour; everyday tasks stay neutral. Deadlines are thin markers under the day's date (amber only on the day itself), and the all-day strip is labelled "untimed".

## Features & UX

- **2026-09-29 — PWA uses `registerType: 'prompt'`.** It shows an "Update ready — reload" toast and never auto-reloads, so an active focus session isn't interrupted.
- **2026-09-29 — Calendar export offers an `.ics` download plus "Copy calendar text". There is no live subscription URL.** A subscribable URL needs a server. If Phase 12 sync lands, Supabase storage could host one.
- **2026-09-29 — PDFs are stored as Blobs in `files` and opened in a new tab via object URL, not embedded in iframes.** This avoids CSP/plugin issues. Snapshots exclude blobs, and JSON export includes them only on request.
- **2026-09-29 — Cloud sync (Phase 12) is deferred.** Supabase with last-write-wins on `updatedAt`, tombstones as schema v2, and lazy-loaded so it costs nothing when off. We'll decide on `@supabase/supabase-js` vs plain fetch at that point. The app works fully without it.
- **2026-09-29 — A lazy chunk that fails to load (usually after a deploy) reloads the tab once, then offers "Reload".** `RouteErrorView` recognises the browser's dynamic-import failure messages (`logic/chunkError.ts`) and calls `location.reload()` at most once per 30 s per tab, guarded by `sessionStorage['forge:chunk-reload-at']`; if storage is unavailable it never reloads on its own. "Try again" is not offered for these, because `React.lazy` caches the rejected import.
- **2026-09-29 — Startup and database failures render a full-screen recovery page, never a blank one.** `app/start.tsx` boots, then renders once. A rejected boot shows "Forge could not start", and a boot still pending after 10 s shows "taking a while" (an IndexedDB open blocked by another tab hangs silently; if boot finishes later, the app replaces the screen). Both offer Reload and a raw JSON export. Another tab upgrading or deleting the database (`versionchange`, handled in `boot.ts`, not `db.ts`) closes this tab's connection for good and shows "Forge was updated in another tab". Uncaught errors and unhandled rejections go to `recordError`.
- **2026-09-29 — Storage.** Boot asks `navigator.storage.persist()` once, without waiting for it. The raw export reads all tables in one read transaction and embeds attached files as base64 only while they total under 50 MB, otherwise it lists them and says so in `notes`.
- **2026-09-29 — Navigation is announced.** After a pathname change (not on first load, not on query-only changes) focus moves to the page `<h1>` (or `<main>`) and a polite live region announces the page title. Focus is left alone when the page already put it somewhere (an autofocused field) or a modal holds it.
- **2026-09-29 — Quick add highlights tokens with a transparent textarea over a copy of its text (Phase 3B).** The copy paints a soft tag-colour background behind each recognised token; the textarea on top keeps the real caret, selection, IME and paste. It wraps and grows to four lines instead of scrolling sideways, because a copy cannot follow a horizontal scroll reliably, and it uses a halo (`box-shadow`) rather than padding so the two layers never drift. Chips carry the same information for screen readers, and a live region reads them out.
- **2026-09-29 — Bare `daily`, `weekly` and `weekdays` are recurrence only in the tail of a quick-add line.** They need a title word before them and only tokens after them ("Water plants daily #home"); otherwise they stay in the title ("Weekly review", "Daily standup notes", "Review weekly notes"). `every …` forms always count. A recurrence word at the start of a title was the common false positive.
- **2026-09-29 — Quick add is a portaled dialog, not a native `<dialog>`; the palette is a native `<dialog>`.** Toasts must show above quick add (Shift+Enter keeps it open and the "Added to …" toast has an Open button), and the top layer would hide them. Quick add makes `#root` inert while open and pushes the `modal` shortcut scope; opening the palette, quick add or the sheet closes the other two first, so nothing sits behind the palette's top-layer dialog.
- **2026-09-29 — `Toast` gained a generic `action` button (`{ label, onClick }`), shown before Undo.** Quick add's "Added to Upcoming · Open" needs it; clicking it runs `onClick` and dismisses the toast.
- **2026-09-29 — Palette order and recents.** Groups are Recent (empty query only), Actions, Pages (the "Go to" commands plus any provider group called "Pages"), then provider groups (Tasks, Goals, Courses, others A to Z). Commands rank by fuzzy title match, then by keyword prefix. Provider results keep the provider's own filtering; the palette re-ranks them by fuzzy title match and highlights it. Recents are stored in `localStorage` (`forge:palette:recent`, 8 kept, 5 shown): a command by id, a search result as title, subtitle, group and provider id, and it is found again through its provider when chosen (a deleted one falls back to searching for its title). `/` opens the palette in search mode (no actions).
- **2026-09-29 — The shortcut sheet filters by word prefix, not fuzzily.** Every word must start a word of the description, group, scope or keys; a query that is part of some shortcut's keys ("g t", "ctrl k") shows just those. A fuzzy match over a whole row finds almost anything, which is wrong for a list of about sixty rows.
- **2026-09-29 — Task lists (Phase 3A).** Inbox is your own open tasks that are not tied to a goal or course, whatever their date (the Today screen's "Your tasks"); Upcoming is open work due after today; All is every open task; Completed is finished work grouped by the day it was done, with the time and the XP each task earned. View settings (group, sort, filters) live in the address bar (`group`, `sort`, `dir`, `status`, `priority`, `tag`, `course`, `due`), so a filtered list survives a reload and can be bookmarked. Dragging is available only in manual, ascending order, and only within a group.
- **2026-09-29 — The task peek is a portaled side panel driven by `?peek=<id>`, replacing history entries.** It floats over the page like Notion's side peek instead of squeezing the list, and it is rendered into `<body>` so the page's entrance transition cannot offset it. Below 640 px there is no room beside the list, so a peek link becomes the `/task/:id` page. Opening and closing replace the history entry (Back leaves the page), and `j`/`k` while it is open moves it to the next task.
- **2026-09-29 — Completion motion is a small state machine in `TaskActionsProvider`, not CSS alone.** The write starts on click (so the Undo toast and the real XP amount are known), the row is held on screen while `checking → struck → leaving` (fill, strike-through and gold "+N XP", then 600 ms later the slide-out), and released 300 ms after that. A held row is drawn as still open even though the database already says done, so filters and groups do not pull it away mid-animation. Reduced motion keeps the same timing but only fades: movement is built from `--shift-*`, and the collapse is switched off.
- **2026-09-29 — A row is one big click target (a stretched button behind the content) that opens the task; the title button is only as wide as its text.** Clicking the text edits in place (Enter commits, Esc reverts, leaving commits); clicking anywhere else opens the peek. On coarse pointers the title opens the task instead, so a tap never raises the keyboard. Selecting a row by click never scrolls it, because scrolling between pointer-down and pointer-up swallows the click; only `j`/`k` reveal the selection.

## Design system

- **2026-09-29 — Theme tokens work on any element (Phase 2A).** The selectors are `:root, [data-theme='light']`, `[data-theme='dark']`, and a `prefers-color-scheme: dark` block for `:root:not([data-theme])` / `[data-theme='system']`. That block repeats the dark values, and `contrast.test.ts` fails if the two drift. This lets `/design` nest a dark column inside a light page.
  - Accent presets set raw `--_accent-*-l/-d` values on `[data-accent]`. Each theme block maps them to the public `--accent*` tokens, so the mapping re-resolves inside a nested theme. To preview an accent on a sub-tree, set both `data-accent` and `data-theme` on it.
  - Colour tokens are literal hex or `rgba()` only, so the test can parse and composite them. Shorthands that reference theme colours (such as `--focus-ring`) are declared on `:root, [data-theme]` so they resolve per theme.
- **2026-09-29 — Colour naming and contrast tiers (WCAG AA, enforced by `src/styles/contrast.test.ts`).** The surfaces are `--bg`, `--bg-sidebar` and `--bg-elevated`, each plain, with `--bg-hover` and with `--bg-active`.
  - `--text` and `--text-muted` reach at least 4.5:1 on every surface. Use them for all small text, including placeholders and keyboard hints.
  - `--text-faint` reaches at least 3:1. Use it only for large text (≥ 24 px, or ≥ 18.66 px at weight 700), icons, disabled text and decorative separators.
  - `--{accent,success,warning,danger,xp}` are for fills, icons, bars and rings, at least 3:1.
  - `--{…}-text` is coloured text, at least 4.5:1 on the surfaces and on its own `--{…}-soft` tint.
  - `--accent-contrast` is text on an `--accent` or `--accent-hover` fill, at least 4.5:1.
  - `--bg-inverse` with `--text-inverse` and `--text-inverse-muted` is for tooltips and toasts.
  - `--border` and `--border-strong` are decorative hairlines, not held to 3:1. Controls are identified by their label or text and by the focus ring.
- **2026-09-29 — Minimal colour changes to meet AA.** The rest of the brief's values are unchanged.
  - Light `--text-muted`: 0.65 → 0.72 alpha. The brief's value is 4.2:1 on white.
  - `--text-faint`: light 0.45 → 0.56, dark 0.35 → 0.38, to reach 3:1.
  - Blue accent: `#2383E2` → `#2376D4`, because white text on the brief's blue was 3.9:1.
  - Light `--xp`: `#CB912F` → `#BE8226`, so it reaches 3:1 as a fill.
  - Warning, danger and XP get darker `-text` variants in light mode.
  - Shell edits: the tab-bar labels, the sidebar `Ctrl K` hint, the placeholder "Coming soon" line and the phone date on Today moved from faint to muted. `--on-accent` was renamed `--accent-contrast`.
- **2026-09-29 — Six accent presets, following `AccentId`: blue (default), teal, green, orange, pink and graphite.** Graphite replaces the suggested red, because red would read as `--danger`.
  - A colour accent uses one fill in both themes. White text needs 4.5:1 on it and the fill needs 3:1 against `#252525`, which leaves a narrow window.
  - Hover is darker. Dark mode gets a lighter `--accent-text` and a stronger `--accent-soft`.
  - Graphite is near-black with white text in light mode, and light grey with `#191919` text in dark mode.
- **2026-09-29 — Tag colours are opaque soft backgrounds with same-hue text, at least 5:1 in both themes.** `--tag-<name>-text` doubles as the colour for dots, icons and confetti (at least 3:1 on the page).
- **2026-09-29 — Reduced motion collapses the movement tokens and adds a safety net.** It applies under `[data-reduced-motion='on']`, and under `prefers-reduced-motion` unless the attribute is `off`.
  - `--shift-1/2/3` become 0 and `--scale-in`/`--scale-press` become 1, so components that build their transforms from these tokens become opacity-only.
  - Everything else finishes its transitions and animations instantly. Elements whose motion is already token-based opt out with `data-motion="opacity"` and keep their fades (toasts, "+15 XP", the level-up moment).
  - Delays are kept, because they are timing (tooltip delay, the 600 ms slide-out), not motion.
- **2026-09-29 — Global styles load from one entry, `src/styles/index.css`.** The order is typography, tokens, accents, tags, reset, global, motion. The extension (Phase 9) needs `tokens.css`, `accents.css` and the Inter file. `/design` state demos can force the focus ring with `[data-force~='focus']`.
- **2026-09-29 — Primitives (Phase 2B) share a few conventions.**
  - State rules only swap private `--_*` variables, so `:hover`, `:active` and `[data-force~='hover|active|focus']` (the `/design` demos) stay identical. Hover rules sit inside `@media (hover: hover)` so a tap on a phone does not leave a control stuck in hover; the `data-force` twins sit outside it.
  - Coarse pointers get a 44 px hit area through an invisible `::after` (Checkbox grows its invisible native input instead), so controls keep their dense visual size.
  - Shared helpers live in `src/ui/internal/` (`cx`, `useMergedRef`, `useControllable`, the roving-focus `nextIndex`, `useIndicator` for sliding thumbs/underlines, the `ForceProps` type). They are internal: the `src/ui` barrel should not export them.
  - React 19 passes `ref` as a prop, so components spread it through `...rest` instead of using `forwardRef`.
- **2026-09-29 — The danger Button is outlined, not filled.** White on `--danger` is under 4.5:1, and deeper red tints push `--danger-text` below it too. Rest is `--danger-text` with a 45 % `--danger` hairline; hover and press add `--danger-soft`, which the contrast test already covers.
- **2026-09-29 — Interactive tags tint by at most 8 %.** Mixing a tag's text colour into its background by 10 % or more drops some hues under 4.5:1 (computed for all 18 pairs). Hover uses 5 % plus a hairline, press 8 % (worst case 4.52:1).
- **2026-09-29 — New tokens: `--bg-raised`, `--skeleton`, `--skeleton-shine`.** `--bg-raised` is a control lifted off a tinted track (the segmented-control thumb): white in light, `#383838` in dark, because `--bg-elevated` (`#252525`) is darker than a tinted track in dark mode. `contrast.test.ts` checks `--text`/`--text-muted` (4.5:1) and `--text-faint` (3:1) on it. The skeleton pair is a bone and the band that sweeps across it; the band is white in both themes but much weaker in dark.
- **2026-09-29 — Tooltip is hand-positioned with a pure `place()` function (unit-tested), rendered in a portal, and copies the trigger's `data-theme`, `data-accent` and `data-reduced-motion`.** It opens on hover after 500 ms and at once on keyboard focus (`:focus-visible`), never on touch; Esc, pointer down, blur and scroll close it, and the pointer can move onto it (WCAG 1.4.13). While one tooltip is open or just closed, the next opens without delay and replaces it, like macOS. IconButton's tooltip repeats its name, so it is not wired as `aria-describedby`; the shortcut goes to `aria-keyshortcuts` instead.
- **2026-09-29 — Checkbox completion hook.** Becoming checked (not mounting checked) plays a fill from the rim inward, a small pop and a drawn tick, then fires `onCheckAnimationEnd`, which Phase 3 chains into the strikethrough, "+XP" and slide-out. With reduced motion the fill is instant, the tick fades, and the callback still fires. `--cb-color` recolours one instance (priority).
- **2026-09-29 — Kbd formats specs itself (`ui/Kbd/format.ts`) instead of `lib/keys.formatKeys`.** macOS orders modifiers the Apple way (⇧⌘S, not ⌘⇧S) and uses ↩/⌫; sequences keep their chords apart ("G then T"); screen readers get words ("Command K"), and `ariaKeyShortcuts()` builds `aria-keyshortcuts` values.
- **2026-09-29 — `/design` (Phase 2E) conventions.**

## Export

- **2026-09-30 — Export (CSV, Markdown, `.ics`) is built on the device from Dexie, with no dependency.** Pure writers live in `src/logic/export/`; `src/features/export/` adds the Settings section "Export & calendar", palette commands ("Export tasks as CSV", "Export tasks as Markdown", "Download calendar (.ics)"), chords `o c` / `o m` / `o i`, and an `ExportMenu` for the tasks toolbar.
  - CSV is RFC 4180 with CRLF rows; the download carries a UTF-8 BOM so Excel reads accents.
  - `.ics` uses floating local time (no `TZID`, no `VTIMEZONE`): Forge stores wall-clock `HH:mm`, DST cannot shift a block, and there are no zone rules to go stale. Only `DTSTAMP` is UTC. All-day events use `VALUE=DATE` with an exclusive `DTEND`. UIDs are `<taskId>@forge` (also `due-`, `milestone-`, `goal-`, `assessment-` prefixes), so a re-import updates events instead of duplicating them.
  - **No subscribe URL.** A live "subscribe" link needs a server that serves the calendar at a URL Google or Apple can poll; Forge is a static, offline-first app with no server, and a `data:` or `blob:` URL is not reachable from another device or from Google's servers. So the brief's "copy-paste link" becomes "Copy calendar data" (the `.ics` text) plus a one-line import hint. Revisit if Phase 12 sync adds a backend.
